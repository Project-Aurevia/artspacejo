# SEO & GEO Plan — Art Space JO

Search and answer-engine plan for the Art Space domain (every URL below is written against
`<SITE_URL>`, the env var that decides the real origin): what is wrong today, the URL and content
architecture that fixes it, the bilingual keyword map that drives it, and the schema,
crawl-governance and performance work that turns rankings into citations.

Scope: the **public** surface only. `/admin`, `/api/*`, `/media` beyond public assets, and the
client dashboard are private and must never be indexed.

---

## Current state

| Area | Finding |
|---|---|
| Rendering | Single React SPA, `createRoot` on an empty `#root`. Every word of copy is injected by JS |
| Routing | No router. `src/App.jsx` regexes `window.location.pathname` for `/admin` and renders `<Site/>` otherwise — **everything public shares one URL** |
| Indexable URLs | 1 (`/`). `sitemap.xml` emits exactly `['/']` |
| Crawlable content | Zero. Non-JS crawlers and most AI retrieval agents receive `<!doctype html>` + empty `<div id="root">` + one `<noscript>` sentence |
| Title / description | Hardcoded Arabic in [`index.html`](../index.html:8); swapped client-side by a `useEffect` in [`Site.jsx`](../src/Site.jsx:1088). One pair for the whole business |
| Canonical | Injected by the server, always `href="$base/"` — correct for one URL, wrong the moment a second page exists |
| Structured data | A single bare `LocalBusiness` node ([`server/index.js`](../server/index.js:320)). No `Organization`, `WebSite`, `Service`, `OfferCatalog`, `FAQPage`, `BreadcrumbList`, no `sameAs`, no `geo`, no `openingHours` |
| Language | `<html lang="ar" dir="rtl">` server-side; the toggle only mutates client state. No `/en` or `/ar` URL, so no hreflang, no per-language ranking, and switching language loses nothing in the index because there is nothing in the index |
| `robots.txt` | `User-agent: *` only. AI retrieval bots (`OAI-SearchBot`, `PerplexityBot`, `ClaudeBot`, `Google-Extended`) are neither named nor explicitly permitted |
| `llms.txt` | Missing |
| Internal links | Header, footer and every CTA are `#anchors` on one document. No crawlable paths to topic-level pages |
| Admin lockdown | `X-Robots-Tag: noindex, nofollow` on `/admin` ✅; `Disallow: /admin`, `/api/` ✅ |
| Social / OG | Absolute `og:image` rewrite ✅, full OG + Twitter card set ✅, but English-first copy under `lang="ar"` and no per-page differentiation |
| Fonts | Three Google Fonts families load from one render-blocking stylesheet ([`index.html`](../index.html:34)). `display=swap` is already on the URL ✅ — the remaining cost is the blocking CSS request itself |
| LCP risk | The hero `<h1>` is the LCP element — it cannot paint until 3 font families resolve. No hero image (good), but fonts are the bottleneck |

**The single blocking defect:** the site has one URL and no server-rendered text. Until that
changes, nothing else in this plan can rank or be cited, because there is no document for an
engine to read, no page to target a keyword with, and no per-topic URL to earn a link to.

## Phase 1 — Rendering & routing

### Decision: keep the SPA for interaction, server-render the content

Rewriting the app into SSR (Next/Remix) would break the admin panel, the offline cart, the
`localStorage` state model and the 794 px document renderer for no SEO gain. The calculator and
the CRM belong to the SPA; **the marketing copy does not**.

Architecture:

```
/                      SPA shell  — interactive calculator, quote cart, forms  (stays as-is)
/en/<service>          static HTML — server-rendered, zero JS, own copy + schema
/ar/<service>          static HTML — server-rendered, zero JS, own copy + schema
/admin, /api/*         private, noindex
```

- **Landing pages are generated by the server**, not by React: real `<h1>`, real paragraphs,
  real `<a href>` links, real `<style>` — one HTTP request, no bundle, no hydration. This is
  simultaneously the SEO fix, the GEO fix and the Core Web Vitals fix.
- **`/` keeps the SPA** and gains a `<noscript>`-independent identity: canonical `/`, its own
  `WebSite` + `LocalBusiness` nodes, and crawlable `<a href>` links into every landing page so
  link equity flows and crawlers discover the set from the home page.
- **Language = path prefix.** Arabic is the default market (`/ar/...`), English is secondary
  (`/en/...`), `/` is the bilingual SPA and stays `x-default`.
- **Slugs stay Latin** (`/ar/signage-amman`). Arabic slugs percent-encode into unreadable
  sitemap and log noise, and Google treats URL tokens as a weak signal — the Arabic keyword
  belongs in `<title>`, `<h1>` and body, where it actually counts.

### Admin lockdown (verified, keep)

- `X-Robots-Tag: noindex, nofollow` on `/admin` — [`server/index.js`](../server/index.js:298)
- `robots.txt` disallows `/admin` and `/api/`
- Add `<meta name="robots" content="noindex">` on the SPA route when `pathname` starts with
  `/admin` is unnecessary — the header already covers it, and keeping the SPA shell `noindex`-free
  avoids poisoning `/`.

## Phase 3 — On-page & semantic HTML

Per landing page:

1. **One `<h1>`** carrying the primary keyword, not the brand. `Signage Company in Amman —
   Facades, 3D Letters & Lightboxes`.
2. **`<h2>` per sub-service**, `<h3>` for materials/specs, never skipping a level.
3. **Landmarks**: `<header>` → `<nav aria-label>` for the service set, `<main>`, `<section>`,
   `<nav aria-label="Breadcrumb">`, `<footer>`, plus a visible `BreadcrumbList` rendered as
   `Home › Signage Company in Amman` with real `<a href>` links — **two levels, not three**.
   There is no `/services` index page, so a middle rung would point at a page that is not an
   ancestor (or at a 404), and Google only honours breadcrumbs whose `item` URLs resolve.
4. **Unique meta per page**: title ≤ 60 chars with city + service, description 140–160 chars
   with a concrete differentiator and the phone number, canonical self-referencing.
5. **hreflang**: `en`, `ar`, `x-default` → `/`, reciprocal on every pair.
6. **Image discipline**: no decorative `<img>` in the hero (the `<h1>` is the LCP element);
   when real project photos land, `width`/`height` set, `loading="lazy"` below the fold,
   `fetchpriority="high"` + `decoding="sync"` for the first one, descriptive bilingual `alt`
   that names the material and the city rather than "project image".
7. **Internal links**: every page links to the other five services, to `/#calculator`, and to
   `/llms.txt` (for agents). The SPA footer gains the same set as real links.
8. **Contact affordances**: `tel:`, `mailto:`, WhatsApp deep link — all crawlable, and mirrored
   in `Organization` schema.

## Phase 4 — Crawl governance, schema & GEO

### 4.1 Schema graph (one `@graph` per page, `@id`-linked)

| Node | Purpose | Key properties |
|---|---|---|
| `ProfessionalService` (⊂ `LocalBusiness` ⊂ `Organization`) | The business entity | `@id /#org`, `name`, `alternateName` (AR), `url`, `logo`, `image`, `telephone`, `email`, `address` (`PostalAddress`, `addressLocality Amman`, `addressCountry JO`), `geo`, `areaServed` (`Amman`, `Irbid`, `Zarqa`, `Aqaba`, `Jordan`), `openingHoursSpecification`, `priceRange`, `currenciesAccepted JOD`, `sameAs` (social profiles), `knowsLanguage ["ar","en"]`, `hasOfferCatalog` |
| `WebSite` | Site identity + language | `@id /#website`, `name`, `inLanguage`, `publisher → #org` |
| `WebPage` | Per URL | `@id <url>#webpage`, `isPartOf`, `about → #org`, `inLanguage`, `primaryImageOfPage` |
| `BreadcrumbList` | Path context | `itemListElement` with real URLs |
| `Service` | Per landing page | `name`, `serviceType`, `provider → #org`, `areaServed`, `offers` (`Offer`, `priceCurrency JOD`, `priceRange` or `priceSpecification`) |
| `OfferCatalog` / `Offer` / `AggregateOffer` | Packages, materials, price ranges | `itemOffered`, `price`, `priceCurrency`, `unitText` (`m2`, `month`, `piece`). Each landing page's `Service.offers` is an `AggregateOffer` computed from the price table **as rendered** (`lowPrice`, `highPrice`, `offerCount`), so the schema can never quote a number the page does not show |
| `FAQPage` | The conversational queries above | `mainEntity[] Question/acceptedAnswer` |
| `ImageObject` | Social card + project photos | `contentUrl`, `width`, `height`, `caption` |

**Deliberately excluded:** `aggregateRating` and `Review` on the business. The testimonials in
`DEFAULT_CONTENT` are sample rows — marking them up would be a manual-action risk. Add
`Review` only when verified, named, real client reviews exist.

### 4.2 `robots.txt`

Explicitly **allow** the retrieval bots (they are what get you cited) and **name** the training
bot separately so the decision is conscious, not accidental:

```

Allow: /
Disallow: /admin
Disallow: /api/

User-agent: Googlebot
Allow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: ChatGPT-User
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: Claude-SearchBot
Allow: /

User-agent: Bingbot
Allow: /

User-agent: Google-Extended
Allow: /

Sitemap: <base>/sitemap.xml
```

### 4.3 `sitemap.xml`

One `<url>` per real page with `xhtml:link` hreflang alternates, `lastmod` from content
changes, and real `priority`/`changefreq`. Anchors are not URLs and must not appear.

### 4.4 `llms.txt`

Plain-text map at `/llms.txt` (plus `/llms-full.txt` later if copy grows): who the business is,
what it sells, service URLs with one-line descriptions, pricing model, contact, and a
"This site prices projects with a public calculator" line — the fact that makes an assistant
quote you instead of a competitor.

### 4.5 GEO content rules

1. **Answer first, then explain.** Every FAQ answer opens with the direct answer in one sentence;
   AI extraction takes the first 40–60 words.
2. **Hard numbers on the page.** Prices, lead times ("5–7 working days"), areas served, years in
   business, project counts. Numbers are what get quoted with attribution.
3. **One idea per paragraph**, `<h2>` phrased as a question where the query is a question.
4. **Entity completeness** — the same `Organization` facts on every page, in schema, in the
   footer, and in `llms.txt`.
5. **Cite-ability over keyword density** — a paragraph that survives being lifted out of context
   is worth more than a paragraph that repeats "signage Amman" six times.
6. **`dateModified`** in `WebPage` so assistant caches refresh.

## Phase 5 — Core Web Vitals

| Metric | Current risk | Fix |
|---|---|---|
| **LCP** | Hero `<h1>` is the LCP element and waits on one render-blocking Google Fonts stylesheet carrying three families. `&display=swap` is already set ✅ | Landing pages sidestep it completely: fonts load non-blocking (`media="print" onload="this.media='all'"`) and paint starts from a system stack. On the SPA, the remaining win is dropping unused weights from the font URL |
| **CLS** | Font swap on large display type | explicit fallback metrics, no layout-affecting animation above the fold |
| **INP** | 225 kB admin/public bundle on the SPA | landing pages ship **0 kB JS**; on the SPA, the calculator stays behind its section and the cart is already local |
| **TTFB** | SQLite read per request in `page()` | cache the rendered shell + JSON-LD graph in memory, invalidate on settings write |
| **Transfer** | OG PNG + font subsets | serve AVIF/WebP for project photos, subset Arabic to the glyphs used, `Cache-Control: immutable` on hashed assets (already correct) |

## Phase 6 — Measurement & maintenance

### Controls to configure once

| Control | Where | Why |
|---|---|---|
| `SITE_URL` set to the public origin | `.env` | Canonical, hreflang, `sitemap.xml`, `llms.txt` and the `Sitemap:` line in `robots.txt` are all absolute. Unset, they fall back to the request host — fine behind a proxy that forwards the public host, silently wrong (`http://127.0.0.1:3000`) when it does not. The server now warns at boot when it is missing in production |
| Google Search Console + Bing Webmaster Tools | DNS or HTML verification | Submit `/sitemap.xml` once; 13 URLs should be discovered |
| AI-answer spot checks | ChatGPT, Perplexity, Gemini, Copilot | Monthly, ask "who does signage in Amman" and "كم تكلفة لوحة إعلانية في الأردن"; log whether the domain is cited, linked, or absent |
| Core Web Vitals field data | GSC → CWV | Needs real traffic; do not chase lab-only scores |
| Conversion tracking | Existing forms + `tel:` clicks | The KPI is quote requests and calls per landing page, not sessions |

### Regression checks after any deploy

```sh
curl -s localhost:3000/sitemap.xml | grep -c '<loc>'                    # expect 13
curl -s localhost:3000/robots.txt | grep -E 'OAI-SearchBot|Sitemap'
curl -s localhost:3000/ar/signage-amman | grep -o '<h1[^>]*>[^<]*'      # Arabic H1, no JS
curl -sD- localhost:3000/admin -o /dev/null | grep -i x-robots-tag      # noindex, nofollow
```

Plus a scripted pass that `JSON.parse`s every `application/ld+json` block and asserts exactly one
`<h1>`, one self-referencing canonical and three hreflang links per page, with `FAQPage`,
`BreadcrumbList` and `AggregateOffer` present on every landing page.

### Content cadence
